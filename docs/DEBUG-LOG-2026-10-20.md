# Debug Log — 2026-10-20 — "The apps won't launch"

Goal: make both packaged apps launch like the reference
HCR Probe Designer.app. Outcome: **both apps launch to their Shiny UIs**
(user-verified). This log preserves the root causes so they are never
re-introduced.

## The decisive reference finding

`codesign -dv` on the shipped HCR Probe Designer.app:
**"code object is not signed at all"** — outer bundle, Electron Framework,
everything. HCR's `identity: null` means *no signing whatsoever*. The entire
previous signing campaign (bottom-up ad-hoc signers, `--deep`, Team-ID
analysis) was solving a self-inflicted problem.

## Bugs, in order of discovery

### 1. Hardened-runtime ad-hoc signing → dyld rejection
- **Evidence:** crash report `CRISPR Designer-2026-10-20-192113.ips`:
  DYLD "Library missing", "mapping process and mapped file (non-platform)
  have different Team IDs"; `flags=0x10002(adhoc,runtime)` on old builds.
- **Cause:** our pipeline ran `codesign --force --deep --sign - --options
  runtime`. The runtime flag switches on dyld library validation, which
  rejects the unsigned Electron frameworks.
- **Fix:** removed all Electron-side signing; deleted tools/sign-app.js.
  Posture now identical to HCR (verified on all three apps).

### 2–4. Path-resolution bugs (bootstrap/r-runtime)
- `resolveRRuntime` looked in `Resources/r`; the packager layout puts R at
  `Resources/app/r`. Payload expected flat in `Resources/app`, actually at
  `Resources/app/payload/`. `APP_SCRIPT` was never set, so runner.R stopped
  with "App script not found".
- **Fix:** dual-layout `resolveRRoot()` (shared by r-runtime.js and
  bootstrap), payload-aware `resolveAppDir()`, `APP_SCRIPT` set in spawn env.

### 5. R segfault at dyn.load — THE subtle one
- **Evidence:** replicating the exact spawn: R printed `APP_LIBS=`, then
  `*** caught segfault ***` inside `requireNamespace("shiny")` → `dyn.load`
  (SIGSEGV, pid 74620). Base R ran fine; only package loading crashed.
- **Cause:** the package closure lives in a separate `shared/r/library`
  tree that `fix-r-framework.sh` never patched (it only walked the
  framework's own Resources). Package `.so` files still referenced
  `/Library/Frameworks/.../libR.dylib`. Because the *bundled* libR's install
  id had been rewritten to `@loader_path`, dyld could not match the
  dependency against the already-loaded image — it opened the system path
  and mapped a **second copy of libR** into the process → duplicate R state
  → segfault. (On machines without system R it fails differently: "image
  not found".)
- **Cross-check vs HCR:** the shipped HCR app patches only `exec/R`
  (entry-point) and leaves libR's install name as the absolute system path —
  dyld then *matches* package `.so` deps against the loaded image instead of
  double-loading. HCR's source installs packages INSIDE the framework
  library, so its fix script covers them; our separate-tree layout needed
  the script extended.
- **Fix:** `fix-r-framework.sh` rewritten with `patch_tree()`/`sign_tree()`
  applied to both the framework and the sibling `library/` tree.
  Result: 47 additional load-command rewrites, 142 more binaries re-signed,
  **0** absolute references remaining.
- **Verification:** runner simulation printed `APP_PORT=33343`, served the
  Shiny UI, `curl` → HTTP 200.

### 6. `startApp is not a function` (user-reported dialog)
- **Evidence:** dialog text from launching the 19:52 build; line
  `main.js:10:1`.
- **Cause:** bootstrap.js was brace-mangled from an earlier edit —
  `createLoadingWindow`/`onShinyReady` nested inside `spawnR`, a dangling
  `}` after `module.exports`. `node --check` passed (braces balanced) but
  `module.exports = { startApp }` sat inside a dead function scope, so the
  export was `{}`.
- **Fix:** complete clean rewrite of bootstrap.js. Regression test that
  would have caught it: `node -e "typeof require('./shared/electron/
  bootstrap').startApp"` must print `function` — now part of the runbook.
- Also fixed in the rewrite: preload resolution (generated preload sits at
  the staged app root, not beside bootstrap) and a console mirror writing
  `<userData>/main.log` (packaged stdout is detached under LaunchServices —
  this file is what finally made failures visible).

### 7–9. Smaller fixes
- `stage-app.js` pointed at a nonexistent `shared/reference/…` pJAT source
  (real location: `shared/r/janelia_atalanta_plasmids`).
- `build-app.js` `copyTree` recreated symlinks with absolute targets
  (machine-specific); now preserves the original link text.
- Dead `apps/*/desktop/` scaffolding from an abandoned electron-builder
  attempt removed (crispr at Phase 0; plasmid found during documentation).

### 10. Plasmid "CLI mode requires --gene" (user-reported)
- **Evidence:** fatal-error screen: `.run_pjd_cli()` → stop.
- **Cause:** Plasmid_Designer.R's trailing standalone dispatch had no
  `sys.nframe()` guard, so runner.R's `--args <payload dir>` looked like a
  CLI invocation. Cas9_sgRNA_design.R already used the guard — which is why
  CRISPR worked first.
- **Fix:** wrapped the dispatch in `if (sys.nframe() == 0L)` (commit 6555437).
  Standalone `Rscript` behavior unchanged. Verified by simulation
  (`APP_PORT=59750`, HTTP 200) before rebuild; user-verified after.

## Lessons

1. **The reference app is the spec.** Diff against it before inventing
   solutions (the unsigned discovery reframed everything).
2. **dyld install-name dedup** is the whole game for bundled R: either keep
   libR's install name matching what package `.so`s expect (HCR's shipped
   app) or rewrite every `.so` too (our approach). Half-patching = segfault.
3. **Never claim success without observation.** Base-R smoke tests passed
   while shiny loading segfaulted; "process started" ≠ "window appeared".
   The runbook's three gates exist because of this.
4. **Observability first.** The main.log mirror turned an invisible failure
   into a one-file diagnosis.
